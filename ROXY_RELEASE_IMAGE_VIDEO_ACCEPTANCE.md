## 3. Database Schema Verification (`generated_images`)

The `generated_images` table schema was updated in Alembic revision `011_trust_reliability_hardening` and verified on the live NeonDB instance:
- `id`: UUID Primary Key
- `user_id`: UUID Foreign Key referencing `users.id`
- `prompt`: Original user prompt
- `revised_prompt`: Enriched/expanded prompt generated by the LLM
- `image_url`: Storage URL or base64 data URI
- `style_preset`: Preset applied (e.g., `photorealistic`, `cinematic`, `anime`, `digital_art`, `isometric`)
- `width` / `height`: Resolution dimensions (e.g., `1024x1024`, `1792x1024`)
- `seed`: Integer generation seed for reproducible synthesis
- `is_favorite`: Boolean bookmarking flag
- `vault_document_id`: Optional UUID linking the image asset to the Knowledge Vault
- `created_at`: Timestamp

---

## 4. Media Storage & Fallback Architecture

- **Primary Storage:** Object storage bucket (AWS S3 / Google Cloud Storage compatible).
- **Staging / Local Storage:** Static asset directory `/static/generated_images/` with HTTP asset serving.
- **Asynchronous Processing:** Video rendering and image upscaling jobs are managed via background asyncio tasks with progress percentage reporting (`0%` to `100%`).
